# Персональные данные: подготовка к публикации

Футер содержит доступные ссылки `/privacy` и `/consent` на всех публичных страницах. Запросы и отзыв согласия описаны в `/privacy#requests`. Декоративный ASCII-логотип рисуется на Canvas; стили — Tailwind. Документы пока **проекты**, а не подтверждение соответствия 152-ФЗ.

## Что реализовано

- Единственный источник действующих текстов — `back/privacy.py`, публичный `GET /api/privacy`.
- Пустой отдельный чекбокс согласия в форме. Политика вынесена отдельной ссылкой.
- API проверяет готовность документов, явно выраженное согласие и SHA-256 актуального текста. Обход чекбокса не позволяет сохранить заявку.
- Заявка и точный снимок политики/согласия сохраняются в одной транзакции. Новая таблица `contact_consents` создаётся существующим `init_db()`; старые заявки не получают фиктивных согласий. При удалении заявки через API удаляется и связанное доказательство согласия.
- Юридические страницы рендерятся на сервере без кэша и читаются без JavaScript. При недоступности API показан явно обозначенный резервный проект, форма закрыта для отправки. Баннер cookies не добавлен: в проверенном коде нет аналитики/рекламы; язык хранится в localStorage. Настройки production-прокси и хостинга этим не проверены.

## Что должен заполнить оператор

Публичные настройки `site_settings` (существующий авторизованный `PUT /api/site/settings/{key}`, тело `{"value":"…"}`). Не хранить здесь секреты: настройки доступны всем посетителям.

| Ключ | Содержание |
| --- | --- |
| `privacy_operator` | Полное ФИО/наименование, статус, применимые регистрационные реквизиты |
| `privacy_address` | Адрес для обращений |
| `privacy_hosting` | Провайдеры сайта, основной БД, резервных копий; страны размещения; фактические условия локализации и передачи |
| `privacy_recipients` | Кто имеет доступ, обработчики, их наименования/адреса, назначение и основания доступа; либо подтверждённое отсутствие иных получателей |
| `privacy_retention` | Конкретные сроки хранения заявки, согласия, журналов и копий, событие начала срока, порядок удаления; срок согласия |
| `privacy_security` | Реальные организационные и технические меры, контроль доступа, резервирование, реагирование на инциденты |
| `privacy_approved` | `true` — только после заполнения и проверки текстов и фактических процессов |

Не включать `privacy_approved` ради снятия блокировки. Автоочистка по срокам, удаление из резервных копий и мониторинг инцидентов этой задачей не реализованы. Их нужно настроить под выбранную инфраструктуру. Изменение любого текста меняет версию согласия, ранее открытая форма потребует обновления. При изменении настроек сначала выключить `privacy_approved`, обновить сведения, проверить страницы и затем утвердить.

До публичного сбора проверить необходимость и наличие уведомления Роскомнадзора по ст. 22, локализацию по ч. 5 ст. 18, поручения обработчикам, фактическую защиту по ст. 19, порядок запросов/уничтожения и уведомлений об инцидентах. Уведомления от имени владельца не отправлялись. Неизвестные сведения не выдуманы.

Правовая сверка: 21.10.2026. [152-ФЗ, официальный сайт Минтруда](https://mintrud.gov.ru/docs/laws/130), [ст. 18.1](https://www.consultant.ru/document/cons_doc_LAW_61801/eeeebe22bf738fd65bb66b95cc278911ae2525ee/), [ст. 9, редакция от 26.07.2026, отдельное согласие](https://www.consultant.ru/document/Cons_doc_LAW_61801/6c94959bc017ac80140621762d2ac59f6006b08c/). Прямое открытие РКН и pravo.gov.ru в текущем сеансе недоступно; это ограничивает проверку первоисточников. Перед утверждением нужен повторный просмотр действующей редакции и фактических условий оператора.

## Проверки и резервный проект

`python -m unittest discover -s back/tests -v`: 6 тестов. Проверяются блокировка, смена версий, совпадение резервного проекта и реальные ASGI-маршруты с временной SQLite: отказ без согласия, создание заявки со снимком документов, отклонение старой версии, удаление связанной записи. Тест не читает конфигурацию/секреты и не подключается к рабочей БД. PostgreSQL-миграцию нужно проверить отдельно перед развёртыванием: production-БД в этой работе не изменялась.

При правке `back/privacy.py` обновить резервный проект из корня:

```powershell
python -c "import sys,json,pathlib; sys.path.insert(0,'back'); from privacy import privacy_document; pathlib.Path('front/src/lib/privacyDraft.json').write_text(json.dumps(privacy_document({}),ensure_ascii=False,indent=2)+'\n',encoding='utf-8')"
```
