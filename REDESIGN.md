## 1. Аудит: что есть на самом деле

Аудит проводился по коду, а не по README — README отстал от реальности.

### 1.1 Расхождения README и кода

`README.md` в разделе «Статус» помечает как «next» то, что уже сделано:

| README говорит | В коде на самом деле |
|---|---|
| «Контент — следующая фаза» | `PortfolioItem`, `Translation`, `SiteSetting` в `back/models.py`; страницы `front/src/pages/admin/Content.tsx`, `Portfolio.tsx` |
| «Сообщения — следующая фаза» | `ContactMessage` + `/api/contact`, `/api/messages*`; `front/src/pages/admin/Messages.tsx` |
| не упомянуто | Кастомные домены гостей (`Project.custom_domains`, `/api/projects/{slug}/domains`) |
| не упомянуто | Шифрованные env-переменные гостей (`ProjectEnvVar`, `back/secrets_box.py`, Fernet) |
| не упомянуто | Рейт-лимит (`back/ratelimit.py`), сидеры (`seed_portfolio.py`, `seed_translations.py`) |

**Действие:** привести раздел «Статус» в README в соответствие после первого этапа работ.

### 1.2 Чего нет вообще (важно для задачи 4)

Мониторинг отсутствует полностью — это не доработка, а новая подсистема:

- В `back/engine.py` нет ни одного вызова `docker stats`. Есть только
  `build_image`, `ensure_db`, `run_app`, `wait_healthy`, `stop_project`,
  `start_project`, `destroy_project`, `app_logs`.
- В `back/models.py` нет ни одной таблицы под замеры нагрузки или события.
- Логи гостя (`app_logs`) отдаются только разовым срезом (`tail`), стрима нет.

### 1.3 Что мешает новому дизайну

- Акцент `#C4B5FD` (лаванда) захардкожен в трёх местах: `tailwind.config.js`
  (токены `lav` / `lav-dark` / `lav-bg`), `src/index.css` (`::selection`),
  и палитрами прямо внутри компонентов — `S0Intro.tsx` содержит `PALETTE_A` /
  `PALETTE_B` литералами.
- Фон `body` — белый (`#FFFFFF`), а не `#1D1D1D`.
- Текущий hero — «глитч-плашка со сменой палитры по ховеру»
  (`useColorDoubtGlitch`). Это другой жанр, чем референсы; он уходит.
- Секции главной жёстко привязаны к полноэкранному скроллу
  (`useSectionScroll`, `body.home-page { overflow: hidden }`) — новый макет
  Lunora-типа требует обычного скролла со сценой в первом экране.

**Не выбрасываем:** GSAP, Lenis, framer-motion, `useSplitReveal`,
`MagneticButton`, `CustomCursor`, i18n (ru/en), весь бэкенд контента.

## 2. Дизайн-решения

### 2.1 Палитра

| Токен | Значение | Назначение |
|---|---|---|
| `ink` | `#1D1D1D` | основной фон, тёмная база |
| `accent` | `#E5BDDF` | акцент: CTA, подсветка, hover, `::selection`, рассвет |
| `ink-soft` | `#2A2A2A` | приподнятые поверхности, карточки |
| `paper` | `#F4F1F0` | текст на тёмном; фон светлой темы |
| `muted` | `#8A8A8A` | вторичный текст |

Поскольку тем две (см. 2.4), цвета описываются **семантическими
CSS-переменными** (`--bg`, `--fg`, `--surface`, `--accent`), а токены выше —
их значения в тёмной теме. Tailwind ссылается на переменные, а не на хексы —
иначе под каждую тему пришлось бы дублировать классы.

Старые `lav*` удаляются из `tailwind.config.js` после миграции компонентов.
Локальные палитры внутри компонентов заменяются на переменные — литеральных
цветов в `.tsx` быть не должно (сейчас они есть в `S0Intro.tsx`).

### 2.2 Типографика — сериф-дисплей + гротеск (жанр Lunora)

- **Заголовки:** Instrument Serif (или Fraunces как альтернатива) — крупные,
  светлые, с италикой для выделения ключевого слова, как «*Resources*» на
  скрине Shine.
- **Тело и UI:** Onest — уже подключён, остаётся.
- **Моно:** JetBrains Mono — остаётся для админки, логов, техданных.

Подключение — через `@import` в `index.css`, как сейчас.

### 2.3 Hero — океан под луной, WebGL на three.js

Атмосфера берётся от Lunora (3-й скрин): ночь, глубина, свечение, ощущение
живого мира. Сюжет — свой: **океан, над горизонтом луна, дорожка лунного
света бежит по волнам прямо на зрителя**.

Кадр: full-bleed, камера низко над водой, горизонт в верхней трети. Вода
занимает большую часть кадра — так лунная дорожка идёт «в лицо» зрителю и
даёт максимум погружения.

**Вода — кастомный шейдер, не готовый `three/examples/Water`.**
Причины: (1) готовый Water рендерит сцену дважды ради планарных отражений —
дорого; (2) его демо узнаваемо, а сайт-портфолио не может выглядеть как чужой
пример; (3) настоящий вид лунного света на воде — это не зеркальное отражение
диска, а **дрожащая дорожка бликов на гранях волн**, и она считается
аналитически, дешевле и точнее.

- Волны Gerstner: 4-5 наложенных волн разной длины и направления — дают
  острые гребни и пологие впадины вместо «синусоидального желе».
- Блик: анизотропный specular по нормалям волн → дорожка сама собой
  дробится, мерцает и сужается к горизонту.
- Френель: у горизонта вода зеркальная и светлая, под камерой — тёмная и
  глубокая. Это то, что создаёт ощущение масштаба.
- Пена на гребнях самых высоких волн, едва заметная.

#### Смена темы = движение небесной сферы

Ключевое решение: **у сцены один ведущий параметр** — угол `sunAngle` на
дуге небосвода. Всё остальное — производные от него. Луна и солнце сидят на
одной оси в 180° друг от друга: когда одно заходит, другое встаёт. Это не
две сцены с кроссфейдом, а одна сцена с одним числом.

Переключение темы гонит `sunAngle` на 180° по часовой стрелке за **~2.5с**:
луна кренится к горизонту и тонет в океане, небо светлеет, встаёт солнце.

От `dayFactor` (0 = ночь, 1 = день) зависят: градиент неба, цвет и
прозрачность воды, цвет блика, плотность тумана у горизонта, прозрачность
звёзд и облаков, экспозиция.

**Акцент `#E5BDDF` — это рассвет.** Переход физически проходит через
розово-сиреневую фазу у горизонта. То есть акцентный цвет проекта — не
краска, наляпанная поверх сцены, а момент восхода. Он же остаётся в лунном
гало ночью и в кромке облаков днём.

| | Ночь (тёмная тема) | День (светлая тема) |
|---|---|---|
| Небо | `#1D1D1D` → глубокий сине-фиолетовый | светлый, тёплый у горизонта |
| Светило | луна + гало `#E5BDDF` | солнце, тёплый блик |
| Небесный слой | звёзды + Млечный Путь | облака |
| Вода | почти чёрная, дорожка холодная | бирюзово-серая, блики дробные |

Звёзды и облака не «переключаются» — они кроссфейдятся по `dayFactor`:
звёзды гаснут по мере рассвета, как в жизни.

#### Живой мир

То, ради чего сцена «чувствуется живой» — редкие незапланированные события,
которые нельзя предугадать:

- **Падающая звезда** — ночью, случайно раз в 20-40с, в случайной части неба.
- **Облака** днём медленно плывут и меняют форму (FBM-шум, не спрайты).
- **Дыхание волн** — амплитуда медленно гуляет, море то успокаивается, то
  поднимается.
- **Птица** днём — изредка пересекает кадр у горизонта.
- **Лунная дорожка** реагирует на курсор: камера чуть кренится, дорожка
  смещается вместе с ней.

Правило: события **случайны по времени, но не по частоте**. Если падающая
звезда летит по таймеру каждые 10с — мир мёртвый и механический.

#### Прочее

- Параллакс по курсору — камера кренится на несколько градусов, не больше.
- Скролл через Lenis: камера уходит к горизонту, текст hero всплывает.
- Текст hero живёт **внутри** сцены — брызги и блики проходят перед буквами.
- Вход: сцена проявляется из темноты за ~1.2с на первой загрузке.

Ограничения и подстраховка:

- `prefers-reduced-motion` — статичный кадр, волны замирают, событий нет.
  Переключение темы остаётся, но мгновенное, без анимации небосвода.
- Нет WebGL / слабое устройство — фолбэк на статичный градиент неба и воды в
  цветах текущей темы. Сайт обязан работать без сцены.
- Пауза рендера, когда вкладка не активна и когда hero ушёл из вьюпорта.
- Мобильные: меньше волн в Gerstner-сумме, ниже плотность звёзд, DPR ≤ 2.
- Бюджет: +~150кб gzip (three.js), отдельным чанком, не блокирует первый
  рендер.

### 2.4 Тема сайта

Переключатель меняет **тему всего сайта**, а не только сцену — иначе он
воспринимается игрушкой в hero.

- Ночь → тёмная тема (`#1D1D1D` основной), день → светлая (`paper`).
- Первый визит — по `prefers-color-scheme`, дальше выбор живёт в
  `localStorage`.
- Тема задаётся атрибутом на `<html>`, цвета секций — через CSS-переменные,
  чтобы не дублировать классы Tailwind на каждый блок.
- Тема применяется **до первого paint** (инлайн-скрипт в `index.html`), иначе
  будет вспышка не той темы при загрузке.
- Админка остаётся тёмной — там свой контекст, и `body.admin` уже отделён.
- Обе темы обязаны проходить контраст AA. Акцент `#E5BDDF` светлый: на
  светлой теме он не годится для текста и мелких элементов — там он работает
  заливкой под тёмным текстом.

### 2.5 Структура главной

Уход от полноэкранного посекционного скролла к обычному вертикальному:

1. **Hero** — WebGL-сцена, сериф-заголовок по центру, один CTA.
2. **Работы** — карточки из `PortfolioItem` (данные уже есть в БД).
3. **Подход / О себе** — переиспользуем `S2About`, `S3Method` в новой палитре.
4. **Контакт** — форма на существующий `/api/contact`.

Тонкие направляющие линии-рамки (приём со скрина Shine) — как сквозной
графический мотив разделов.

## 3. Админка — редизайн

Та же палитра, но плотнее: это рабочий инструмент, а не витрина.
Фон `#1D1D1D`, поверхности `#2A2A2A`, акцент `#E5BDDF` — только на действиях
и активных состояниях, не на декоре. Никакого WebGL и кастомного курсора
(`body.admin` уже отключает его — оставляем).

Навигация: Дашборд · Под-сайты · Контент · Портфолио · Сообщения · Настройки.
Отдельного раздела «Аналитика» нет — мониторинг живёт внутри карточки
под-сайта, там же, где им пользуются.

**Дашборд** переделывается из счётчиков статусов в сводку:
суммарная нагрузка по всем гостям, проблемные стенды наверху (упавший
healthcheck, рестарты, высокий CPU), последние события деплоя.

**Карточка под-сайта** становится центром управления, вкладками:
Обзор (статус, домены, аптайм) · Нагрузка (графики) · Логи ·
Env-переменные · Домены · Опасная зона.

Графики — на `dataviz`-подходе, лёгкая библиотека, без тяжёлых дашборд-китов.

## 4. Подсистема мониторинга нагрузки

**Метрика посещений исключена из объёма.** Под-сайты — это тестовые стенды,
которые крутятся в ходе разработки; считать на них «сколько людей зашло»
нечего и незачем. Соответственно не делаем: JS-пиксель, `/api/collect`,
парсинг access-логов Caddy, таблицы визитов, хэширование IP и фильтрацию
ботов. Мониторинг остаётся, но он инженерный: он отвечает на вопрос «что
происходит с моим стендом», а не «кто на него пришёл».

### 4.1 Нагрузка — свой сборщик `docker stats` → Postgres

Без Prometheus/cAdvisor: экономим ~500МБ RAM на VPS и два контейнера.

- Фоновая задача в панели раз в **15с** снимает stats со всех гостевых
  контейнеров (`<slug>_app`, `<slug>_db`) через уже смонтированный
  `docker.sock`.
- Пишет в таблицу `metric_samples`: CPU %, RAM (used/limit), сеть (rx/tx),
  диск (read/write), timestamp, project_id, container.
- **Ретеншн:** сырые точки живут 48ч → сворачиваются в часовые срезы, которые
  хранятся 30 дней. Годовых срезов не делаем: для dev-стендов история глубже
  месяца бессмысленна, а без неё нет и третьего уровня агрегации.
- Размер БД гостя — отдельно, реже (раз в час), через `pg_database_size`.

Новые модели: `MetricSample`, `MetricHourly`.

### 4.2 Что показываем в админке

Всё — под задачу отладки стенда:

- Графики CPU / RAM / сеть / диск за 1ч / 24ч / 7д / 30д с переключателем.
- Здоровье: время ответа `/healthz`, счётчик рестартов контейнера — сразу
  видно контейнер, который циклически падает и поднимается.
- Аптайм: процент времени в статусе `running` за период.
- Размер БД гостя в динамике — ловит распухание данных на стенде.
- Алерты (позже): healthcheck упал, CPU > X% дольше N минут, диск растёт.

## 5. Порядок работ

Этапы независимы и дают рабочий результат каждый — не «большой взрыв».

1. **Токены и типографика.** CSS-переменные, палитра `#1D1D1D` / `#E5BDDF`,
   шрифты, чистка `lav*` и литеральных цветов. Сайт временно «перекрашен»,
   но цел.
2. **Механика тем.** Атрибут на `<html>`, `localStorage`,
   `prefers-color-scheme`, анти-вспышка до первого paint, светлые варианты
   секций. Делается **до** сцены: сцена подключается к готовому `dayFactor`,
   а не наоборот.
3. **Hero-сцена.** Пошагово: вода Gerstner → небо и `sunAngle` → луна и
   дорожка → звёзды/облака → живые события. Фолбэки и отвязка от
   `useSectionScroll`. Каждый шаг проверяется в браузере.
4. **Остальные секции главной** под новый макет, обе темы.
5. **Бэкенд мониторинга.** Модели `MetricSample` / `MetricHourly`, сборщик
   stats, свёртка в часовые срезы, эндпоинты выдачи агрегатов.
6. **Редизайн админки** + вкладки карточки гостя, включая «Нагрузку».
7. **README** — привести «Статус» в соответствие (см. 1.1).

## 7. Что сознательно НЕ делаем

- **Метрика посещений** — под-сайты это dev-стенды, аудитории у них нет.
  Отменяет: JS-пиксель, `/api/collect`, парсинг access-логов, `VisitEvent` /
  `VisitDaily` / `BotFilter`, хэширование IP, гео по IP, фильтры ботов.
- **Публичный статус-пейдж** гостевых сайтов — следует из того же: стенды не
  предназначены для внешней аудитории.
- **Prometheus / cAdvisor** — см. 4.1, свой сборщик дешевле по RAM.
